## 实际改进

- 执行前重新检查批准摘要、暂停、保护版本、额度与审核时间，部分计划重试只处理剩余对象。
- 模型接口拒绝歧义密钥、非法端口、错误消息角色、矛盾停止状态和伪造的实际版本；双0.9阈值未改变。
- 文档、备份、安装包、压缩归档、临时下载的分类与缺失证据更明确。通用XML可以进入文档待复核，不因扩展名永久保留，也不直接授权删除。
- 引用路径、打开文件、未知使用时间和跳过路径报告更准确。没有把“未观察到引用”改写成“没有引用”。
- 损坏的授权、计划和时钟数据明确报错或停止；导入及制品验证约束目录、凭据、输出量和运行时间。
- 旧授权与当前保护上下文不一致时停止；缺失保留起点或隔离后元数据证明时拒绝清空。旧安全策略版本的计划需要重新预览和批准。
- 文件比较即使失败也累计实际读取量；恰好用满预算允许完成当次校验，再阻止新工作。
- 根目录和保护路径拒绝越界或符号链接；关闭句柄不会再误用复用的描述符，复制描述符保持不向子进程泄漏。
- 调度输出对路径、名称与特殊字符正确引用；救援报告保留损坏manifest对应关系，仍允许恢复现有字节。

## 下一步改进方案

1. **真实判定语料。** 按文档、临时文件、归档、近期使用、仍被引用、可恢复副本建立有所有者答案的中文样本；分别记录误放行、误保留和不确定，不以合成服务通过代替真实准确性。
2. **补齐实际事实。** 将只读盘点中的使用与引用信号，在可校验的同一文件身份和快照下接入审核；逐项记录探测时间、覆盖目录、权限失败和跳过项。未读到最近使用时间、未找到引用都保留为有限范围证据，不能当成不再需要。文档需有被替代、用途终止或所有者确认等处置依据。先证明事实绑定，再优化正例放行率。
3. **完成双模型真实验收。** 当前剩余1次调用不足以新增一组完整JEV＋MiniMax双调用验证，扩大调用前需明确新增总额度；沿用原阈值，不用调低阈值换通过。
4. **目标机验证。** 本机组合检查通过后，服务器上的代理连通性、Linux运行与正式发布制品仍需在真实目标环境验证。调度引用按 [systemd环境变量语法](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#Environment=) 和 [specifier语法](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html#Specifiers) 修正，单元字符串测试不代替目标机运行。
5. **空间效果计量。** 分开报告候选逻辑大小、实际隔离量、待清空量和清空后的可用空间增量；同卷隔离不声称释放空间。首次实际使用先保留可恢复路径，再独立验收到期清空。
6. **再考虑正式启用。** 只有具体候选用途、处置依据、引用覆盖、可恢复性、模型结论及独立执行权限均可核对后，才另行决定恢复调度。到期清空仍需独立批准，旧隔离对象不自动获得新权限。

100轮是本次限定测试与改进任务的完成数，不是安全保证或模型效果评分。后续开发优先解决真实证据和模型验收缺口，不再为增加轮数扩展代码。
